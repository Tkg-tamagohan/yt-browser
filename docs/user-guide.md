# yt-browser 導入と使い方

mpv による軽量な再生と、ローカル完結の購読と履歴と NG 管理を一体化した YouTube 専用ブラウザ（専ブラ）です。
この文書はエンドユーザー向けの導入手順と操作方法をまとめたものです。

## 動作要件

- OS: Linux（WebKitGTK 4.1 環境、配布物は Ubuntu 24.04 相当以降を対象）または Windows 10 以降
- 必須の外部コマンド（いずれも PATH から解決される必要がある）
  - `mpv`: 再生エンジン
  - `yt-dlp`: ストリーム解決と検索
- 推奨
  - `deno`: YouTube の解読を yt-dlp が外部 JS ランタイムに委ねる環境で必要になる

### 依存コマンドの導入例

Ubuntu / Debian の場合。

```sh
sudo apt install mpv yt-dlp
# もしくは新しい yt-dlp が必要なら
# sudo curl -L https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp -o /usr/local/bin/yt-dlp && sudo chmod +x /usr/local/bin/yt-dlp
```

Windows の場合は winget を使えます。

```powershell
winget install mpv mpv
winget install yt-dlp.yt-dlp
winget install DenoLand.Deno
```

インストール後は、新しいターミナルや再起動で PATH が通ることを確認してください。

## インストール

GitHub Releases から配布物を取得します。

- Linux: `*.AppImage`（実行権限を付けて起動）、`*.deb`、`*.rpm`
- Windows: `*-setup.exe`（NSIS インストーラ）

ソースから動かす場合は次のとおりです。

```sh
pnpm install
pnpm tauri dev        # 開発起動
pnpm tauri build      # AppImage / deb / rpm を生成（src-tauri/target/release/bundle 以下）
```

## 画面と機能

ナビゲーションは左のタブで切り替えます。

### 再生（トップ）

- URL または動画 ID を入力して「再生」で動画を開きます（既定は PiP の最前面・枠なし小窓です）
- 「通常窓で再生」は設定を変えずに通常ウィンドウで起動します。設定で既定を通常窓に戻すと、このボタンは「PiP で再生」に変わります
- 再生中のインスタンスはプレイヤーカードとして並び、複数同時再生に対応します
- プレイヤーカードのループボタンで「なし → 全体 → 1 項目」を切り替えられます。全体はキューの末尾から先頭へ戻り（キューが無い再生では現在項目を繰り返し）、1 項目は現在項目だけを繰り返します
- ループボタンの右にある「A-B」ボタンで A-B リピートを使えます。押すたび「A 点設定 → B 点設定（ループ開始）→ 解除」の順に変わります。ループはその再生中だけ有効で、連続再生やキューで別の動画へ切り替わると解除されます
- 「スクリーンショット」ボタンで、再生中のフレームを字幕込みの PNG で保存します。保存時のトーストに出る「フォルダを開く」から保存先フォルダを開けます
- プレイヤーカードの「概要欄を表示」で再生中動画の概要欄を開閉できます。本文中の URL はクリックで既定ブラウザ、`mm:ss` 形式の時刻表記はクリックでその位置へシークします。連続再生やループで再生中の動画が切り替わると内容を取り直します
- プレイヤーカードの「リンクをコピー」で、再生中の動画タイトルと YouTube の視聴ページ URL をクリップボードへコピーできます（タイトルが未取得の動画は URL のみになります）
- プレイヤーカード一覧の上部にある「PiP を整列」で、すべての PiP 窓を対象モニター上に格子状に並べ直します。対象は設定の「起動ディスプレイ」で、自動ならプライマリモニターです。PiP 窓の無いときと Wayland 環境では無効表示になります。mpv 0.38 未満の環境では動作せずエラーになります
- プレイヤーカードの「前面に出す」で、そのインスタンスの mpv 再生窓を最前面に出します。Windows と Linux の X11 環境で使えます。Wayland 環境ではボタンが無効表示になります（プロトコルの制約）。起動直後など mpv 窓がまだ作られていないときはエラーになります
- 視聴履歴に途中再生の位置が残り、「続きから再生」で再開できます

### キュー

- 検索・フィード・関連動画・ライブラリの各動画行にある `Q＋`（キューに追加）と `Q▶`（次に再生）でキューへ積み上げられます。追加するだけでは再生は始まりません。Chrome 拡張からも動画を追加できます（「Chrome 拡張から開く」節）
- `Q＋` はキューパネルで選択中のキュー（一時キューまたはプレイリストキュー）の末尾へ、`Q▶` は一時キューへ（実行中なら現在項目の直後・未実行なら先頭）入ります。同じ動画の重複登録もできます
- ナビ右端の「キュー」ボタン（括弧内の件数は一時キューのもの）か、キューで再生中のプレイヤーカードの「キュー」ボタンでキューパネルを開きます
- パネル上部のタブで「一時キュー」とプレイリストごとのキューを切り替えます。項目は ↑↓ ボタンやドラッグ＆ドロップで並べ替え、× で個別削除、「残りをシャッフル」で現在位置より後をランダムに並べ替え、「全消去」で一覧を空にできます
- 「プレイリストとして保存」で、選択中キューの項目を順序どおり新しいプレイリストへ複製できます。名前を入力して「作成」を押すとプレイリストができ、元のキューはそのまま残ります。キューに同じ動画が重複して入っている場合、プレイリストでは先に出る位置に 1 件だけ残ります（プレイリストは同一動画の重複を持てません）
- 選択中のキューの「再生」で連続再生を開始します。複数のキューは別々のプレイヤー窓で同時に再生できます。実行中は「連続再生を止める」で継続だけを解除します（再生そのものは止まりません）
- 実行中のキューへ `Q＋` で追加した項目や、並べ替え・シャッフルの結果は、そのまま連続再生へ反映されます
- プレイリストの「ここから連続再生」はそのプレイリスト専用のキューを作ります。途中で止めたキューは「キュー停止中」として位置を保持し、キューパネルの「再生」でその位置から再開できます
- 一時キューは項目と現在位置をアプリのデータベースに保存するため、アプリを終了しても残り、次回起動時に停止中の状態（中断位置を保持）で復元されます。キューパネルの「再生」で保存位置から継続できます
- プレイリストキューも対象プレイリストと現在位置がデータベースに保存されるため、アプリを終了しても残り、次回起動時に停止中の状態でキューパネルのタブへ現れます。項目の一覧はプレイリスト本体から取り直されます（キューに対する個別の削除・並べ替え・シャッフルは保存されません）
- プレイリストキューへ後から項目を増やしたいときは、パネルでそのキューを選択してから `Q＋` で追加してください。キューへ追加した項目はそのキューの実行中にのみ有効で、再起動後の復元には含まれません（項目はプレイリスト本体から取り直されるため。永続化したいときはプレイリストへ追加してからキューを作り直してください）
- プレイリストキューは末尾まで再生し切ると位置を先頭へ戻して残りますが、途中で再生窓を閉じたりエラー終了したりするとキューごと消えます

### ライブ待機

- フィード・検索・関連動画の各動画行にある「待」（配信を待機）で、予約されたライブ配信やプレミア公開を開始まで見張れます
- 登録時に放送開始前かを確認します。すでに放送中の動画は待機登録せず、通知からそのまま再生を始められます。放送予定のない通常動画や終了済みの配信は登録されません。同じ動画の重複登録もされません
- キューパネルの「待機」タブで待機中の一覧を見られます。各行は対象動画と開始予定時刻を表示し、× で個別に解除できます
- 待機中の動画行は「待機中」の印が付き、押すと待機を解除します
- 待機リストはアプリのデータベースに保存されるため、アプリを終了しても残り、次回起動時に見張りを再開します
- 開始予定時刻が分かる配信は直前になると確認間隔が短くなります。開始を検出すると、設定に応じて新しいプレイヤー窓で自動再生するかトースト通知します
- 開始予定から 24 時間を超えて始まらない配信は自動で待機を解除します。すでに終了した配信は通知のうえ待機リストから外れます

### ブックマーク

- プレイヤーカードの「ブックマーク」ボタンで、再生中の現在位置を保存できます。ラベルには保存位置の時刻表記（例: 12:34）が自動で付きます。同じ動画の同じ位置は重複して保存されません
- キューパネルの「ブックマーク」タブで保存した一覧を見られます。各行は動画タイトル・保存位置・ラベルを表示し、新しい保存順に並びます
- 行の位置（時刻表記）をクリックすると、その動画を保存位置から再生します
- 「編集」でラベルを付け直せます（Enter または「保存」で確定、Escape で中止）。空欄にすると時刻表記へ戻ります
- × で個別に削除できます
- ブックマークはアプリのデータベースに保存されるため、アプリを終了しても残ります

### フィード

- チャンネル ID（UC...）、URL、@handle を入力して購読します
- 購読チャンネルの新着が一覧に流れ、未読管理とカテゴリ分けができます
- フィード一覧はカテゴリと種別（動画 / Shorts / ライブ）で絞り込めます。種別「ライブ」はライブ・公開予定・プレミアをまとめて表示します
- 種別フィルタで「Shorts」を明示選択したときだけ Shorts を表示します。「すべて」「動画」の選択では、設定の「フィードに Shorts を表示する」がオフ（既定）の間は Shorts が除かれます
- 新着動画の投稿日時や種別は RSS に載らないことがあり、その場合はバックグラウンドで少しずつ自動補完されます（1 分ごとに最大 20 件ずつ）。確定するまで一覧上は暫定の値のままです。判定に失敗した項目は自動で再試行されます
- 「チャンネル別」チェックで一覧をチャンネル単位のセクションにまとめて表示します
- 「すべて既読」で未読のフィード項目をすべて既読にします（絞り込み中でも全体に効きます）
- 設定の「新着をデスクトップ通知する」をオンにすると、フィード更新で新着を検出したとき OS のデスクトップ通知が出ます（既定はオフ）
- 設定でフィード項目の自動既読を有効にできます。「再生した項目を自動で既読にする」は再生履歴のある項目を、「投稿からこの日数が経過した項目を既読にする」は投稿日時が指定日数を経過した項目を既読にします（いずれも既定はオフ・0 で無効）。アプリの起動時とフィード更新のたびに適用されます
- 一覧末尾の「さらに読み込む」で古い方向へ続きを表示します（1 回 500 件）
- 登録チャンネル一覧はカテゴリで絞り込めます
- 購読チャンネル一覧のチャンネル名をクリックすると、そのチャンネルの新着を即時に再取得し、フィード一覧をそのチャンネルの全期間（既読を含む）に絞って表示します。絞り込み中はヘッダに表示され、解除で全体表示に戻ります
- チャンネル絞り込み中は「このチャンネルの過去動画を取得」ボタンで、そのチャンネルの投稿一覧（動画タブ・ライブタブ・Shorts タブ）を各 100 件ずつ遡って取り込めます。続きは「さらに読み込む」で取得済み位置から遡れます。取り込まれた過去動画は既読扱いで一覧に並びます（Shorts は種別フィルタで「Shorts」を選ぶと確認できます）
- 「今すぐ更新」で手動ポーリングします

### 検索

- キーワード検索に対応します。結果末尾の「さらに読み込む」で 20 件ずつ追加表示できます（最大 500 件）
- 行の「購読」「ブロック」でチャンネル操作ができます
- 関連動画は再生中のプレイヤーカードの「関連動画を表示」で開きます

### ライブラリ

- 履歴タブ: 視聴履歴（途中位置つき）を一覧表示や再生や削除できます。途中位置のある項目には「先頭から再生」も出ます
  - 上部の検索ボックスに入力すると、タイトルやチャンネル名で一覧が絞り込まれます
  - 件数が多いときは末尾の「さらに読み込む」で続きを表示します（検索中もその条件で続きを取ります）
- 履歴の各行にある ☆（お気に入り）、＋（プレイリストへ追加）、`後`（あとで見る）、`Q＋` / `Q▶`（キュー）で、履歴から直接ライブラリやキューへ登録できます
- お気に入りタブ: 動画のお気に入りを管理します
- プレイリストタブ: 任意の一覧を作成して動画を登録できます。YouTube プレイリストの URL をそのまま取り込めます（名前を付けなければ取り込んだプレイリスト名が使われます）
  - 左欄のプレイリストそのものも ↑↓ ボタンまたはドラッグ＆ドロップで並べ替えられます（保存されます）。新しく作成・取り込みしたプレイリストは末尾に入ります。並びは各一覧の「プレイリストに追加」メニューにも反映されます（キューパネルのタブはキューを作った順のままです）
  - 項目は ↑↓ ボタンまたはドラッグ＆ドロップで並べ替えられます（保存されます）
  - 「投稿日時で並べ替え」で投稿日の古い順に一括ソートできます（投稿日のない項目は末尾。投稿日時が後から自動補完されることがあります）
  - 「逆順にする」で項目順をまとめて反転できます（新しい順で取り込んだプレイリストを古い順に変える用途）
  - 各項目の「ここから連続再生」でその項目から順に続けて再生します。次の項目は現在のプレイヤーウィンドウで自動的に始まり、末尾で止まります
  - 項目が多いときは末尾の「さらに読み込む」で続きを表示します
  - 「ここから連続再生」はプレイリスト専用のキューを作ります。実行中は「連続再生中」、停止中は「キュー停止中」のバッジがプレイリスト上部に出ます（詳しくは「キュー」節）
- あとで見るタブ: あとで見たい動画を一時的にためておけます
  - フィード・検索・関連動画・ライブラリの各動画行にある `後` で登録し、もう一度押すと解除できます（登録済みは強調表示になります）
  - このタブでは追加が新しい順に並び、各行の「あとで見るを解除」か行アクションの `後` で一覧から外せます
- 検索タブ: タイトルやチャンネル名でライブラリ全体を横断検索できます
  - 履歴・お気に入り・プレイリスト項目・あとで見るのすべてが対象で、同じ動画が複数にヒットしたときは 1 件にまとめて、ヒットした区分がバッジで表示されます
- 統計タブ: 視聴履歴から集計した統計を表示します
  - 累計視聴時間と履歴の件数、チャンネル別の内訳（視聴時間の多い順・上位 50 件まで）、日別の内訳（日付の新しい順）が出ます
  - 視聴時間は履歴の再生位置からの見積もりです（見終わった動画は動画の長さで数えます）。日付は UTC 基準の暦日で、同じ動画の見直しは上乗せされません
- 履歴・お気に入り・プレイリスト項目を削除すると、画面下のトーストに「元に戻す」ボタンが出ます。トーストが消える前（約 6 秒）に押すと、削除した項目がもとの状態で復元されます。お気に入りの ★ トグルで解除した場合も同じように取り消せます。連続して削除した場合は削除ごとのトーストが出るので、個別に取り消せます

### 設定

- 画質（ytdl-format）のプリセットまたは自由記述
- ホイール音量変化量、再生の既定表示（PiP / 通常窓）、PiP の位置とサイズ、PiP の既定画質（空欄なら全体の画質設定に従う）
- 再生の初期速度（0.25〜4.0、既定 1.0）と初期音量（0〜130、既定 100）。mpv 起動引数で渡すため次回の再生開始から有効で、再生中窓の速度・音量はカード上で変えられます（その変更はセッション限りです）
- 再生窓を開くディスプレイの選択（次回の再生から有効。「自動」は mpv 既定の配置。選択したモニターが外れているときは自動にフォールバックします）
- 「再生完了時に窓を自動で閉じる」（既定はオフ）。オンにすると、連続再生を伴わない最後までの再生で mpv 窓とプレイヤーカードが自動的に閉じられます。キューで末尾まで再生し切った場合も同じです。オフのときは従来どおり終了後も残り、途中終了やエラー終了は設定に関わらず閉じられます
  - PiP の「小窓サイズを動画のアスペクト比に合わせる」がオンのとき、位置とサイズの幅・高さは上限枠として扱われ、小窓は動画の比率に合わせて自動調整されます（縦長動画は細い窓、超ワイド動画は低い窓になります）
- SponsorBlock のカテゴリ別動作（スキップ / 通知のみ / 無効）と、シークバーへの区間帯の表示切替（既定は表示）
- HDR・mpv 引数: トーンマッピング方式・ピーク輝度計測の指定と、mpv への追加引数（空白区切り）。変更は次回の再生から反映されます
- NG フィルタを登録できます
  対象は動画タイトルや動画説明文やチャンネル名やチャンネル ID やチャット本文やチャット投稿者で、種別は部分一致・正規表現・ハイライトから選べます
  ハイライトはチャット発言を除去せず、マッチした発言を強調色で表示します（種別はチャット本文・チャット投稿者の対象にだけ効きます）
  ただし動画説明文は現行の一覧取得経路に説明文フィールドがないため、現時点ではフィルタの評価対象になりません
- NG ユーザー: チャット投稿者を指定した NG フィルタ（chat_author）を専用に一覧・追加・解除できます
  追加は部分一致で登録されます。正規表現の投稿者フィルタや、投稿者を対象にしたハイライトは「NG フィルタ」節で登録・管理します
- ブロック中チャンネルの管理
- カテゴリの管理: チャンネル分類に使うカテゴリの追加と削除に加えて、↑↓ ボタンまたはドラッグ＆ドロップで並べ替えられます（保存されます。プレイリスト一覧と同じ操作です）。並びはフィードの購読パネルやカテゴリ選択にも反映されます
- フィードの「フィードに Shorts を表示する」（既定はオフ。種別フィルタで「Shorts」を選んだときは設定に関わらず表示されます）、「新着をデスクトップ通知する」（既定はオフ）、自動既読（「再生した項目を自動で既読にする」と経過日数。既定はオフ・0 で無効。詳しくは「フィード」節）
- ライブ待機の「配信開始時の動作」: 「新規インスタンスで自動再生」（既定）か「トースト通知のみ」を選べます（`live_wait.action`、設定 `play` / `notify`。詳しくは「ライブ待機」節）
- チャットポップアップの表示: 投稿者名の表示（既定はオフ）、文字サイズ（10〜32px、既定 14）、不透明度（0.2〜1.0、既定 1.0）。開いているポップアップにも即時に反映されます
- アプリの更新: AppImage / NSIS 版は起動時に新バージョンを自動で確認します
  更新があると確認ダイアログが出て、承認でダウンロード・適用・再起動まで進みます
  「今すぐ確認」ボタンで手動確認もできます（deb / rpm 版は対象外のため、GitHub Releases から手動で更新してください）
- 運用: データのエクスポート/インポートとデータベースのメンテナンスを行います
  - 「エクスポート」は購読チャンネル・カテゴリ・設定・プレイリスト（項目を含む）を 1 つの JSON ファイルに書き出します。保存先はファイルダイアログで選びます
  - 「インポート」は書き出した JSON を読み戻します。実行前に確認ダイアログが出ます。読み込むと上記のデータがファイルの内容で置き換わります（マージではないため、ファイルに無い項目は消えます。履歴など対象外のデータは残ります）
  - 「DB サイズ」はデータベース関連ファイル（本体＋WAL/SHM）の合計を表示します
  - 「VACUUM」はデータベースファイルを再構築して空き領域を縮めます（データは消えません）
  - 「孤児行整理」は参照の残っていない不要な行を削除します。実行前に確認ダイアログが出ます

## 再生操作

- mpv 窓上のホイール: 再生中は音量、一時停止中はコマ送り（wheel.lua）
  コマ送りは mpv 窓上のキー操作やカード上のボタンも含め、操作中は音声が出ません
- プレイヤーカード上の操作: 一時停止 / 再開、シーク、音量、速度、画質、音声出力先、字幕、1 コマ送り / 戻り、A-B リピート、スクリーンショット、ブックマーク、PiP 化 / 解除、mpv 窓の前面化、終了、タイトルとリンクのコピー
- 最後まで再生しても mpv 窓とカードは残ります（末尾で一時停止の状態）。設定の「再生完了時に窓を自動で閉じる」をオンにすると、連続再生のない再生完了時に自動で閉じられます
- シークバーはドラッグまたはクリックでその位置へ移り、フォーカス中は左右キーで 5 秒ずつ、Home / End で先頭と末尾へ移れます
  SponsorBlock の区間がある動画では、動作が「無効」でない区間がバー上に色帯で表示され、帯にカーソルを合わせるとカテゴリ名が出ます（帯の表示は設定で切れます）
  画質と音声出力先はカード上でインスタンスごとに変えられます（いずれもセッション内のみ有効）。画質の全体既定は設定画面から行います
  音声出力先は mpv が列挙するデバイスから選びます。一覧を取得できない環境ではデバイス名の直接入力になります
  字幕は「字幕」ドロップダウンで「なし」「自動」または mpv が取得した字幕トラックから選べます（セッション内のみ有効。連続再生で次の動画へ進むと自動選択に戻ります）
- 「チャンネル購読」で再生中の動画のチャンネルをその場で購読登録できます（購読済みは無効表示）
- 動画の読み込みに失敗したときは約 1.5 秒後に 1 回だけ自動で再試行します
  再試行も失敗した場合は従来どおりエラー終了として通知されます
- mpv 標準のショートカットも有効です（q で終了、m でミュートなど）
- プレイヤーカードの「チャットを表示」でチャットパネルを開きます（NG フィルタがそのまま効きます）
- NG フィルタの種別「ハイライト」にマッチした発言は消えずに強調色で表示されます（埋め込みパネル・ポップアップのどちらでも同じ色です）
- ライブ配信ではリアルタイムに流れ、終了済み配信やプレミア公開のアーカイブではチャットリプレイが再生位置に同期して流れます（どちらかは自動判定）。後ろへシークすると表示をいったん消してその時点から流し直します。チャットの内容は保存されません
- パネル見出しの「ポップアップ」でチャットを別ウィンドウに切り離せます（元のパネルは閉じます）。ポップアップは既定で最前面に開き、窓内の「最前面」ボタンで固定を切り替えられます（最後の状態を記憶）。窓の位置とサイズは移動・リサイズで自動的に保存され、次回は同じ位置とサイズで開きます（保存した位置が画面外になっていた場合は位置だけ既定に戻り、サイズは復元されます）。表示は既定で時刻と本文のみで、投稿者名の表示・文字サイズ・不透明度は設定画面の「チャットポップアップ」節で変えられます（superchat / membership のバッジは投稿者名を表示しても出しません）
- ポップアップの「パネルに戻す」で埋め込みパネルへ戻せます（起票元が同じ動画を再生中でなければ無効です）。再生を終了してもポップアップは残ります

## Chrome 拡張から開く（外部起動）

同梱の `extension/` は Chrome 拡張（MV3）で、YouTube の動画・プレイリストを yt-browser で開けます（ストア未公開のため開発者モードで読み込みます）。

1. Chrome で `chrome://extensions` を開き、「デベロッパーモード」を有効にする
2. 「パッケージ化されていない拡張機能を読み込む」でリポジトリの `extension/` フォルダを選ぶ
   - GitHub Releases から使う場合は、添付の `yt-browser-extension-<タグ名>.zip` を展開して同じ手順で読み込みます
3. yt-browser を一度起動してください
   - 起動時に、拡張から yt-browser を呼び出すための登録（Chrome の Native Messaging ホスト定義）が自動で行われます
   - アプリを移動したり更新したりしたときも、次の起動で登録が更新されます
4. YouTube の動画画面かプレイリスト画面でツールバーの拡張ボタンを押すと「yt-browser で開く」「再生位置を引き継いで開く」「キューに追加」「プレイリストへ追加」が出ます。YouTube へのリンク上の右クリックからは「yt-browser で開く」と「yt-browser のキューに追加」（動画リンク上のみ）を選べます

登録が済んでいれば、Chrome の「外部アプリで開きますか」確認も新規タブも出ずに yt-browser で開きます。
yt-browser が起動していなければ起動し、起動中ならそのインスタンスへ URL が渡ります。

「yt-browser で開く」は、動画 URL をその場で再生、プレイリスト URL をライブラリへローカル取り込みします（`watch`+`list` 複合 URL は動画として扱います）。
「再生位置を引き継いで開く」は、見ている動画の現在位置を `t=<秒>` として URL に付けて開き、その位置から再生します。再生位置が取れない・冒頭付近のときは無効です。
「キューに追加」は動画 URL をキューパネルで選択中のキューの末尾へ積むだけで、再生は始まりません（選択がなければ一時キュー）。
「プレイリストへ追加」は、一覧から選んだローカルプレイリストへ見ている動画を追加します。一覧は yt-browser 側のプレイリストから取るため、1 件も無い・取得できないときは選べません。
「キューに追加」と「プレイリストへ追加」は動画ページでのみ有効で、プレイリスト単体のページでは無効です。
対象外のページでは拡張ボタンは無効表示になります。

登録前（yt-browser を一度も起動していない場合など）や登録先のパスが無効な場合は、従来の方式に切り替わります。
このときは新しいタブが前面に開いて Chrome の「外部アプリで開きますか」確認が出るので、承認してください。
拡張ボタンには赤い「!」が付き、ボタンにマウスを重ねると理由が表示されます。
「!」は次に登録経由で開けたときに消えます。
対応するブラウザは Chrome だけで、Edge などでは常に従来の方式になります。

## データの保存場所

設定、履歴、購読はすべてローカルの SQLite に保存されます（アカウント連携はありません）。
視聴履歴は直近 10000 件まで保持し、古いものは起動時に削除されます。

- Linux: `~/.local/share/io.github.tkg-tamagohan.yt-browser/yt-browser.db`
- Windows: `%APPDATA%\io.github.tkg-tamagohan.yt-browser\yt-browser.db`
- ログ: 同ディレクトリ配下の `logs/yt-browser.log`
- スクリーンショット: 同ディレクトリ配下の `screenshots/`（ファイル名は `ytb-<動画ID>-<日時>.png`）

## トラブルシューティング

- 「yt-dlp が見つかりません」: yt-dlp をインストールして PATH を通してください
  設定キー `ytdlp.path` でパスを直接指定する経路も内部実装にはありますが、設定画面に入力欄はなく、SQLite の settings テーブルへの直接書き込みが必要です
- 再生が `Sign in to confirm you're not a bot` で止まる場合は YouTube の bot 判定です
  時間を置いても回復しないときは、後述の「bot 判定の回避（cookies.txt）」の手順に従ってください
- mpv や yt-dlp を直接実行すると再生できるのにアプリ経由だと再生窓がすぐ閉じる場合、cookies.txt が読み取り専用になっている可能性があります
  yt-dlp は終了時にセッション Cookie を同じファイルへ書き戻すため、書き込めないファイルではプロセス自体が異常終了します
  ファイルの読み取り専用属性を外してください
- トップ画面下部の yt-dlp 更新ボタンが失敗する場合、システム管理のパス（/usr/bin 等）では権限不足で `yt-dlp -U` が失敗します
  手動で更新してください
- 描画位置とクリック位置がずれる場合（まれに GPU なし環境で発生）、ウィンドウの再読み込みで回復します
  一時停止中のカードも復元されます

## bot 判定の回避（cookies.txt）

YouTube がお使いの IP からの匿名アクセスを bot と判定すると、yt-dlp のストリーム解決がすべて失敗し、再生窓が開いてすぐ閉じる、といった症状が出ます。
ブラウザのログイン Cookie を yt-dlp に渡すと回避できることが多いです。
なおフィード一覧の取得は yt-dlp を通らない別経路のため、フィード側のエラー（status 500 など）はこの手順では解消しません。

1. Chrome 拡張「Get cookies.txt LOCALLY」などで、YouTube にログインした状態の youtube.com のタブから Netscape 形式の cookies.txt をエクスポートしてください
   `--cookies-from-browser chrome` 方式は、現行 Chrome の App-Bound Encryption で Cookie データベースを復号できず使えません
2. エクスポートしたファイルに `LOGIN_INFO` と `__Secure-3PSID` という名前の行があるか確認してください
   無い場合は未ログインや別プロファイルからのエクスポートなので、ログイン済みのタブでやり直してください
3. 各行はタブ区切り7列で、HttpOnly の Cookie は「ドメイン列の先頭」が `#HttpOnly_` になっているのが正しい形です
   `#HttpOnly_.youtube.com ... LOGIN_INFO` が正しく、`... #HttpOnly_LOGIN_INFO` のように名前列に付く形は壊れているので、名前列から `#HttpOnly_` を外してドメイン列へ付け直してください
4. cookies.txt は書き込み可能な場所に置いてください
   読み取り専用にすると yt-dlp が終了時の書き戻しに失敗して異常終了します
   内容はログイン状態そのものなので、共有ディレクトリや同期フォルダには置かないでください
5. yt-dlp の設定ファイルに以下を記述してください
   Windows は `%APPDATA%\yt-dlp\config`、Linux は `~/.config/yt-dlp/config` です（無ければフォルダごと作成）

   ```
   --cookies "<cookies.txt のフルパス>"
   --extractor-args "youtube:player_client=tv_simply"
   ```

   `--cookies` のパスが空白を含むと分割されるため、引用符で囲んでください

   `player_client=tv_simply` は bot 判定を回避する別クライアントへの切り替えです
   cookies だけで抜けられる環境ならこの行は不要ですが、cookies 込みでも `Sign in to confirm` が残る場合に有効です
6. 動作は mpv より先に yt-dlp 単体で切り分けるのが速いです

   ```powershell
   yt-dlp -v -g "https://www.youtube.com/watch?v=<動画ID>" 2>&1 | Select-String "cookie|ERROR|https://"
   ```

   `Loaded N cookies` のあとにストリーム URL が返れば成功です
   `mpv --ytdl=yes "https://www.youtube.com/watch?v=<動画ID>"` で再生できれば、アプリからも再生できます（mpv の ytdl_hook が同じ yt-dlp 設定を読むため）

「tv_simply client https formats require a GVS PO Token」という警告が出る場合、tv_simply では合成済みフォーマット（itag=18、360p）だけが取れる状態です。
アプリの既定画質式には合成済みフォーマットへのフォールバックがあるためそのまま再生できますが、高画質で見たい場合は yt-dlp ドキュメントの PO Token Guide に従って `po_token` の extractor-args を追加してください。
