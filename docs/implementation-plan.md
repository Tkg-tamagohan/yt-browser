# yt-browser 実装計画

[requirements-definition.md](requirements-definition.md) と [design.md](design.md) に基づくフェーズ別の実装計画。
各フェーズはおおむね 1 PR 単位を目安とし、終了時に受け入れ条件を満たすことをチェックする。

## 前提と環境

- 開発と検証の第一環境は Linux の Devin VM。
  mpv と yt-dlp は `apt` / `pip` / バイナリで入れられる
- Windows ビルドは Windows 環境が必要になるため、必要になった時点で Windows 子セッションまたはユーザー側で検証する
- GUI 実機検証は Devin VM の Chrome ではなく mpv / Tauri 本体の起動確認になるため、画面確認はコンピュータツール経由で行う

## 残課題（全フェーズ完了後の既知事項）

実装フェーズはすべて完了した。
ここに挙げるのは未解消の制限と観察メモであり、いずれも通常利用を妨げない。

### 動作上の制限

- **一時停止中のページ再読み込みでカードが復元されない**：フロントのイベント購読は `player://state` の受信に依存するため、一時停止中は状態イベントが流れずカードが消える
  再生再開で復帰する。
  恒久策はマウント時の `player_list` 再取得だが、変更前のコードも同じ構造であり回帰ではない
- **チャット履歴の再オープン重複**：パネルの開き直しでバックログが再保存され、`chat_logs` の行が増える観察がある
  セッション内 dedup だけで DB 一意制約を持たない設計（Phase 6 決定記録）の範囲内の挙動だが、履歴検索のノイズが問題になるなら item ID の一意制約導入を検討する
- **画質変更時の再解決が稀に 403 になる**：yt-dlp が再発行した署名 URL を YouTube が拒否し、mpv が `No video or audio streams selected` で終了することがある
  一過性で再試行は通る
- **`set_property geometry` の位置オフセットが効かない**：mpv の x11 経路の制約で、ランタイムの geometry 変更はサイズのみ適用される
  位置精度が必要なら起動時 PiP 経路を使う（Phase 7 決定記録に記録済み）

### 環境依存の観察

- **WebKitGTK のヒットずれ**：GPU なし環境で描画位置と入力ヒット領域がずれる事象があり、プレイヤーカードの常時マウント化（PR #15、設計書 §9.4）で実害経路を閉じた
  ほかのリマウント要素でも理論上は起こり得るが現行 UI では未観測。
  発生時の軽い回復手段は `location.reload()`
- **絵文字が豆腐化する**：検証環境のフォント不足が原因でアプリの不具合ではない
  チャットの絵文字表示はフォント環境に依存する
- **新規発言のリアルタイム追従は部分未検証**：検証に使った配信が subs-only で発言が疎だったため、新着メッセージの逐次追従は未確認
  ポーラーの生存と初回取得は確認済みで、発言の多い配信での再確認が残る

### 先送りの拡張

- **Tauri updater**：GitHub Releases での公開運用が始まった段階でプラグイン＋署名鍵＋latest.json を導入する（Phase 8 決定記録）
- **yt-dlp の同梱**：`YtDlpResolver` の解決順は対応済みで、同梱配布は今後の選択肢として残す
- **検索のページングと履歴一覧の上限**：検索 20 件、履歴 500 件（上限 1000）は暫定値
  超過が問題になった時点でページングを検討する
